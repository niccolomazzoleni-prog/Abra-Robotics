Programmare il Unitree G1: architettura DDS, SDK2 e integrazione ROS2

13 luglio 2026Team Abra Robotics16 min lettura
In sintesi: Il G1 EDU espone API via DDS (OMG standard per sistemi real-time). Gli sviluppatori usano unitree_sdk2 su Ubuntu 20.04, collegando il PC di lab alla subnet onboard 192.168.123.x. ROS2 è integrabile grazie alla compatibilità DDS IDL. Attivare sempre debug mode prima di inviare comandi motori.

Il modello software del G1

A differenza di un cobot industriali con controller PLC chiuso, il G1 EDU separa due mondi:

  • PC1 (motion stack) — firmware Unitree per equilibrio e locomozione; non accessibile
  • PC2 (development) — Jetson Orin NX per percezione, pianificazione e applicazioni custom

La comunicazione tra moduli sensori, attuatori e applicazioni passa da DDS (Data Distribution Service), standard OMG adottato anche nell'ecosistema ROS2. Questo permette latenze basse su topic ad alta frequenza (500 Hz sul controllo motori) e pattern request/response per comandi sporadici.

Repository e toolchain

  • unitree_sdk2 — C++, esempi low-level e high-level
  • unitree_sdk2_python — binding Python
  • URDF ufficiali G1 — per Gazebo, Isaac Sim, MuJoCo

Abra consiglia Ubuntu 20.04 LTS su workstation dedicata. Sviluppo nativo su Windows/macOS non è supportato ufficialmente; WSL2 è possibile ma complica l'Ethernet diretto al robot.

Setup rete di laboratorio

  1. Cavo Ethernet PC ↔ switch/payload G1.
  2. IP PC su 192.168.123.0/24 (es. .99 o .222).
  3. Verifica: ping verso 192.168.123.164 (PC2 dev).
  4. Annotare il nome interfaccia (ifconfig / ip a) — serve negli esempi SDK.

Installazione SDK

git clone https://github.com/unitreerobotics/unitree_sdk2.git
cd unitree_sdk2
mkdir build && cd build
cmake ..
sudo make install

Controllo low-level: concetti chiave

Gli esempi in example/g1/low_level/ mostrano il pattern standard Abra insegna nei corsi SDK:

  • Publisher su topic comandi (es. rt/lowcmd)
  • Subscriber su stato motori (rt/lowstate) con verifica CRC32
  • Thread recurrenti a 500 Hz per scrittura comandi e logica di controllo

Ogni comando motore include modalità, coppia (tau), posizione (q), velocità (dq), gains kp/kd.

Caviglia: meccanismo parallelo PR vs AB

Le caviglie G1 usano un parallel mechanism con due modalità:

  • PR mode — controllo pitch/roll (default, allineato URDF)
  • AB mode — controllo diretto attuatori A/B (richiede cinematica custom)

Capire questa distinzione è essenziale per sim2real: policy addestrate in simulazione sul modello URDF devono rispettare la modalità attiva sul hardware.

ROS2: quando conviene

L'SDK nativo minimizza latenza. ROS2 aggiunge interoperabilità con Nav2, MoveIt, pipeline vision standard — utile quando il G1 deve convivere con altri robot in un lab multi-piattaforma.

Workflow tipico Abra per università:

  1. ROS2 Humble su Ubuntu 22.04 (o Foxy su 20.04).
  2. Bridge DDS ↔ ROS2 con RMW compatibile.
  3. Simulazione policy in Isaac/MuJoCo con URDF ufficiale.
  4. Deploy hardware in debug mode, limiti di coppia conservativi.

La ricerca su policy learning sta convergendo verso framework che combinano simulazione ad alta fedeltà, teleoperazione e dataset multi-modali (Noreils, 2024 cita Diffusion Policy e approcci imitation learning come frontiera attiva per la manipulation umanoide).

Mani Dex3-1 e pipeline manipulation

Sulle varianti Ultimate, il controllo dita e la lettura tattile (versione B/C) usano topic dedicati. Per grasping adattivo Abra integra tipicamente:

  • Percezione RGB-D da D435i
  • Stima pose oggetto (model-based o learned)
  • Chiusura dita con force threshold da sensori tattili

Reinforcement learning: note pratiche

Il G1 è target per sim2real, ma Noreils (2024) avverte che molti pilot falliscono per gap tra demo controllate e robustezza operativa. Best practice Abra:

  1. Domain randomization aggressivo in sim (attrito, massa, delay sensori).
  2. Limiti di joint torque nel primo deploy reale.
  3. Logging sincronizzato sim/real per debug drift.
  4. Non saltare la fase teleoperata per validare workspace safety.

Checklist pre-sessione di sviluppo

  • Robot in debug mode (L2+R2)
  • Imbracatura o area libera ≥ 3 m
  • Versione firmware e commit SDK documentati
  • Arresto emergenza: L1+A testato
  • Backup configurazione rete PC

FAQ sviluppo

SDK vs ROS2: quale scegliere?

SDK per controllo motori e bassa latenza; ROS2 per ecosistema lab e integrazione multi-robot. Spesso si usano entrambi con bridge.

Abra supporta lo sviluppo custom?

Sì: formazione SDK, integrazione ROS2, PoC manipulation e sorveglianza. Vedi servizi software.
