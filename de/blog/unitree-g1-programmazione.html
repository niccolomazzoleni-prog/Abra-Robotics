Unitree G1 programmieren: Netzwerk, SDK2 und ROS 2 Schritt für Schritt

Aktualisiert am 9. Oktober 2026Abra Robotics
Kurz gesagt: Programmieren lässt sich nur der G1 EDU. Sie verbinden den PC per Ethernet mit dem Subnetz 192.168.123.x, kompilieren unitree_sdk2 (C++) oder installieren unitree_sdk2_python, testen die Beispiele zuerst in der Simulation mit unitree_mujoco und danach am hängenden Roboter im Debug Mode (L2+R2). ROS 2 Humble kommt mit unitree_ros2 dazu, sobald Sie Nav2, MoveIt oder rosbag brauchen.

Um den Unitree G1 zu programmieren, brauchen Sie drei Dinge: die EDU-Version, einen Ubuntu-PC im internen Netzwerk des Roboters und das offizielle SDK unitree_sdk2. Diese Anleitung folgt der öffentlichen Dokumentation von Unitree (GitHub-Repositorys und Document Center) und nennt bei jedem Schritt die Datei oder Seite, aus der er stammt. Ist der Roboter gerade erst angekommen, beginnen Sie mit Einschalten, Fernbedienung und erstem Aufstehen.

Welcher G1 sich programmieren lässt

Im offiziellen Datenblatt des G1 ist die Sekundärentwicklung nur für den G1 EDU angegeben; der G1 in der Basisversion hat 23 Freiheitsgrade und kein Rechenmodul für die Entwicklung. Die EDU-Versionen reichen von 23 bis 43 DoF, mit optionalem Rechenmodul (Unitree nennt Orin-Module) und optionalen Dex3-1 Händen. In der Preisliste von Abra kostet der G1 Air ab 19.809 € und der G1-U1 EDU (23 DoF, Rechendock mit 100 TOPS) ab 38.005 €, jeweils zzgl. MwSt. Alle Versionen finden Sie auf der G1 Übersichtsseite; bei der Wahl zwischen U1, U2 und den Versionen mit Händen hilft der Leitfaden Welche G1 Version passt.

Architektur: wo Ihr Code läuft

Der G1 EDU hat einen Rechner für die Bewegungssteuerung, den Unitree verwaltet, und einen Entwicklungsrechner (PC2) für den Code der Anwender. Die Repositorys von Unitree, zum Beispiel xr_teleoperate, geben für PC2 die Adresse 192.168.123.164 mit dem Benutzer unitree an. Das Startpasswort stellt Unitree bereit; die Entwickler-FAQ und die LeRobot-Anleitung für den G1 nennen 123. Ändern Sie es, sobald der Roboter in ein gemeinsam genutztes Netzwerk kommt.

Sie haben zwei Möglichkeiten:

  • Code auf dem Laptop: Der PC spricht über DDS auf dem Ethernet-Kabel mit dem Roboter. Das ist der bequemste Weg für Entwicklung und Debugging.
  • Code auf PC2: Sie starten das Programm per SSH auf dem Roboter. Das brauchen Sie für autonomen Betrieb ohne Kabel und für geringere Latenz.
ssh unitree@192.168.123.164

Netzwerk am PC einrichten

  1. Verbinden Sie den PC mit einem Ethernet-Kabel mit dem Roboter.
  2. Stellen Sie die Schnittstelle auf manuelles IPv4: Adresse 192.168.123.99 (von Unitree vorgeschlagen), Netzmaske 255.255.255.0. Verwenden Sie keine Adressen, die der Roboter bereits belegt, etwa .164.
  3. Notieren Sie mit ip a oder ifconfig den Namen der Schnittstelle (enp3s0, eth0...): Alle SDK-Beispiele erwarten ihn als Argument.
  4. Prüfen Sie die Verbindung mit ping 192.168.123.164. Kommt keine Antwort, liegt das Problem im Netzwerk, und die IDE zu öffnen bringt nichts.

Ein eigener Ethernet-Port (auch ein USB-Adapter) vermeidet Konflikte mit dem Netzwerk des Labors.

unitree_sdk2 installieren (C++)

Das README von unitree_sdk2 nennt als Referenzumgebung Ubuntu 20.04, gcc 9.4.0, CPU x86_64 oder aarch64 und CMake 3.10 oder neuer. Auf anderen Ubuntu-Versionen lässt sich das SDK meist kompilieren, getestet ist aber diese Umgebung. Windows ist im README nicht vorgesehen.

sudo apt-get update
sudo apt-get install -y cmake g++ build-essential libyaml-cpp-dev \
  libeigen3-dev libboost-all-dev libfmt-dev
git clone https://github.com/unitreerobotics/unitree_sdk2.git
cd unitree_sdk2 && mkdir build && cd build
cmake .. -DCMAKE_INSTALL_PREFIX=/opt/unitree_robotics
make
sudo make install

make kompiliert auch die Beispiele, die in build/bin/ landen. Die Installation in /opt/unitree_robotics empfiehlt auch der Simulator unitree_mujoco.

Oder Python: unitree_sdk2_python

Der Python-Wrapper setzt Python 3.8 oder neuer und cyclonedds 0.10.2 voraus:

git clone https://github.com/unitreerobotics/unitree_sdk2_python.git
cd unitree_sdk2_python
pip3 install -e .

Bricht die Installation mit "Could not locate cyclonedds" ab, erklärt das README, wie Sie CycloneDDS aus dem Branch releases/0.10.x kompilieren und CYCLONEDDS_HOME setzen. Die Beispiele für den G1 liegen in example/g1/. Ein nützlicher Hinweis aus dem README der Beispiele: G1 und H1-2 verwenden die Nachrichten unitree_hg, Go2, B2 und H1 dagegen unitree_go.

Debug Mode: vor jedem Low-Level-Test

Nach dem Einschalten startet der G1 seine eigene Bewegungssteuerung, die laufend Befehle an die Motoren sendet. Veröffentlichen Sie gleichzeitig auf rt/lowcmd, kollidieren die Befehle und der Roboter vibriert. Das Vorgehen aus der Deploy-Anleitung von unitree_rl_gym:

  1. Schalten Sie den Roboter ein, während er im Gurtgeschirr hängt, und warten Sie auf den Nullmoment-Modus;
  2. drücken Sie L2+R2 auf der Fernbedienung: Der Roboter wechselt in den Debug Mode, die Gelenke sind gedämpft;
  3. erst jetzt starten Sie das Low-Level-Programm.

Im Debug Mode hält der Roboter das Gleichgewicht nicht selbst: Er bleibt hängen, bis Ihr Regler ihn trägt.

Erster Test: die Knöchel bewegen

Das Beispiel g1_ankle_swing_example (Quellcode in example/g1/low_level/) liest rt/lowstate, schreibt rt/lowcmd und lässt die Knöchel pendeln. Aus dem Ordner build:

./bin/g1_ankle_swing_example enp3s0

Ersetzen Sie enp3s0 durch Ihre Schnittstelle. Gibt das Terminal "CRC Error" aus, ist die empfangene Nachricht beschädigt oder entspricht nicht dem erwarteten Typ: Prüfen Sie Kabel, Schnittstelle und SDK-Version.

Für High-Level-Befehle (Stehen, Gehen mit vorgegebener Geschwindigkeit) gibt es g1_loco_client. Er nutzt die integrierte Bewegungssteuerung und wird deshalb außerhalb des Debug Mode gestartet:

./bin/g1_loco_client --network_interface=enp3s0 --get_fsm_id

Die Hände haben eigene Topics, getrennt von der Fortbewegung: Am besten läuft die Regelschleife der Beine in einem Prozess und das Greifen in einem anderen, mit unterschiedlichen Frequenzen.

Erst simulieren: unitree_mujoco

unitree_mujoco ist ein Simulator auf Basis von MuJoCo, der dieselben Nachrichten bereitstellt (LowCmd, LowState, SportModeState, beim G1 die IMU im Torso). Ein Programm, das mit unitree_sdk2, unitree_sdk2_python oder unitree_ros2 geschrieben ist, läuft zuerst in der Simulation und danach auf dem Roboter. Der Simulator unterstützt nur die Low-Level-Entwicklung. Für Reinforcement Learning deckt unitree_rl_gym den Ablauf Train, Play, Sim2Sim (MuJoCo) und Sim2Real für G1, H1, H1-2 und Go2 ab.

Wann ROS 2 dazukommt

Das SDK direkt zu nutzen ist der kürzeste Weg für Motoren und isolierte Tests. ROS 2 brauchen Sie, wenn Sie Nav2, MoveIt, Standard-Pipelines für die Bildverarbeitung, Aufzeichnung mit rosbag oder mehrere Roboter im selben Labor integrieren. Das Paket unitree_ros2 enthält die Nachrichten unitree_hg und ein Low-Level-Beispiel für den G1 (g1/lowlevel/g1_low_level_example); Unitree hat es unter Ubuntu 22.04 mit Humble (empfohlen) und unter Ubuntu 20.04 mit Foxy getestet. Installation, Netzwerk und erstes Topic beschreibt die Anleitung ROS 2 auf Unitree Robotern.

Sicherheits-Checkliste für das Labor

  • Erste Tests immer mit hängendem Roboter und freiem Bereich ringsum.
  • Niedrige Verstärkungen kp/kd und vorsichtige Drehmomentgrenzen in der ersten Regelschleife.
  • Eine Person an der Fernbedienung, bereit, den Roboter in die Dämpfung zu schalten.
  • Dieselbe SDK-Version auf PC und Roboter; nach einem OTA-Update prüfen Sie die Beispiele erneut.

Häufige Fragen

Lässt sich der G1 in der Basisversion (nicht EDU) programmieren?

Nein. Im offiziellen Datenblatt von Unitree ist die Sekundärentwicklung nur für den G1 EDU angegeben; der Basis-G1 hat weder das Rechenmodul für die Entwicklung noch SDK-Zugang.

Welches Betriebssystem braucht der Entwicklungs-PC?

Das README von unitree_sdk2 nennt Ubuntu 20.04 mit gcc 9.4.0 als Referenzumgebung, auf CPU x86_64 oder aarch64. Für ROS 2 hat Unitree Ubuntu 20.04 mit Foxy und Ubuntu 22.04 mit Humble getestet und empfiehlt Humble.

Welche Adresse hat der Entwicklungsrechner des G1?

Der Entwicklungsrechner (PC2) des G1 EDU ist unter 192.168.123.164 erreichbar, Benutzer unitree. Ihr PC kommt mit einer freien Adresse in dasselbe Subnetz 192.168.123.x; Unitree schlägt 192.168.123.99 vor.

Warum vibriert der Roboter, wenn ich ein Low-Level-Beispiel starte?

Fast immer ist die integrierte Bewegungssteuerung noch aktiv und sendet parallel zu Ihren Befehlen eigene. Wechseln Sie in den Debug Mode (L2+R2, Roboter hängend und gedämpft), bevor Sie Befehle auf rt/lowcmd senden.

Besser mit der Simulation oder mit der Hardware beginnen?

Mit der Simulation. unitree_mujoco verwendet dieselben DDS-Nachrichten wie der Roboter. Dasselbe Programm läuft also erst in MuJoCo und dann auf dem G1, nur die Netzwerkschnittstelle ändert sich.
