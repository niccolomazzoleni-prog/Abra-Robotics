Unitree G1 programmieren: Netzwerk, SDK2 und ROS 2 Schritt für Schritt

Aktualisiert am 9. Oktober 2026Abra Robotics
In Kürze: Programmierbar ist nur der G1 EDU. Sie verbinden den PC per Ethernet mit dem Subnetz 192.168.123.x, kompilieren unitree_sdk2 (C++) oder installieren unitree_sdk2_python, testen die Beispiele zuerst in der Simulation mit unitree_mujoco und dann am hängenden Roboter im Debug Mode (L2+R2). ROS 2 Humble ergänzen Sie mit unitree_ros2, wenn Nav2, MoveIt oder rosbag benötigt werden.

Zum Programmieren des Unitree G1 brauchen Sie drei Dinge: die EDU-Version, einen Ubuntu-PC im internen Netzwerk des Roboters und das offizielle SDK unitree_sdk2. Diese Anleitung folgt der öffentlichen Unitree-Dokumentation (GitHub-Repositories und Document Center) und nennt zu jedem Schritt die Datei oder Seite, aus der er stammt. Wenn der Roboter gerade angekommen ist, starten Sie mit Einschalten, Fernsteuerung und erstem Aufstehen.

Welcher G1 lässt sich programmieren

Im offiziellen G1-Datenblatt ist die Sekundärentwicklung nur für den G1 EDU vorgesehen; der G1 base hat 23 Freiheitsgrade und kein Rechenmodul für die Entwicklung. Die EDU-Versionen reichen von 23 bis 43 DoF, mit optionalem Rechenmodul (Unitree nennt Orin-Boards) und optionalen Dex3-1-Händen. In der Preisliste von Abra startet der G1 Air bei 19.809 € und der G1-U1 EDU (23 DoF, 100-TOPS-Rechenmodul) bei 38.005 €, zzgl. MwSt. Alle Versionen finden Sie im G1-Hub; zur Wahl zwischen U1, U2 und den Versionen mit Händen gibt es die Anleitung Welche G1-Version wählen.

Architektur: wo Ihr Code läuft

Der G1 EDU hat einen von Unitree verwalteten Motion-Control-Computer und einen Entwicklungscomputer (PC2) für den Nutzercode. Die Unitree-Repositories, zum Beispiel xr_teleoperate, geben PC2 mit der Adresse 192.168.123.164 und dem Benutzer unitree an. Das anfängliche Passwort stellt Unitree bereit; die Entwickler-FAQ und die LeRobot-Anleitung für den G1 nennen 123. Ändern Sie es, sobald der Roboter in ein gemeinsam genutztes Netzwerk kommt.

Sie haben zwei Optionen:

  • Code auf dem Laptop: Der PC spricht über DDS auf dem Ethernet-Kabel mit dem Roboter. Das ist die bequemste Wahl zum Entwickeln und Debuggen.
  • Code auf PC2: Sie starten das Programm per SSH auf dem Roboter. Nötig für den Betrieb ohne Kabel und um die Latenz zu reduzieren.
ssh unitree@192.168.123.164

PC-Netzwerk einrichten

  1. Verbinden Sie den PC per Ethernet-Kabel mit dem Roboter.
  2. Stellen Sie die Schnittstelle manuell auf IPv4: Adresse 192.168.123.99 (der von Unitree vorgeschlagene Wert), Maske 255.255.255.0. Verwenden Sie keine Adressen, die der Roboter bereits belegt, wie .164.
  3. Notieren Sie mit ip a oder ifconfig den Schnittstellennamen (enp3s0, eth0 ...): alle SDK-Beispiele erwarten ihn als Argument.
  4. Prüfen Sie mit ping 192.168.123.164. Antwortet er nicht, liegt es am Netzwerk: Es bringt nichts, die IDE zu öffnen.

Ein dedizierter Ethernet-Port (auch ein USB-Adapter) vermeidet Konflikte mit dem Labornetzwerk.

unitree_sdk2 installieren (C++)

Das README von unitree_sdk2 nennt als Referenzumgebung Ubuntu 20.04, gcc 9.4.0, CPU x86_64 oder aarch64 und CMake 3.10 oder neuer. Auf anderen Ubuntu-Versionen lässt es sich meist kompilieren, aber getestet ist diese Umgebung. Windows ist im README nicht als Umgebung vorgesehen.

sudo apt-get update
sudo apt-get install -y cmake g++ build-essential libyaml-cpp-dev \
  libeigen3-dev libboost-all-dev libfmt-dev
git clone https://github.com/unitreerobotics/unitree_sdk2.git
cd unitree_sdk2 && mkdir build && cd build
cmake .. -DCMAKE_INSTALL_PREFIX=/opt/unitree_robotics
make
sudo make install

Der make-Schritt kompiliert auch die Beispiele, die in build/bin/ landen. Die Installation nach /opt/unitree_robotics wird auch vom Simulator unitree_mujoco empfohlen.

Oder Python: unitree_sdk2_python

Der Python-Wrapper benötigt Python 3.8 oder neuer und cyclonedds 0.10.2:

git clone https://github.com/unitreerobotics/unitree_sdk2_python.git
cd unitree_sdk2_python
pip3 install -e .

Wenn die Installation mit "Could not locate cyclonedds" stoppt, erklärt das README, wie Sie CycloneDDS aus dem Zweig releases/0.10.x kompilieren und CYCLONEDDS_HOME setzen. Die G1-Beispiele liegen in example/g1/. Ein nützlicher Hinweis aus dem Beispiel-README: G1 und H1-2 verwenden die unitree_hg-Nachrichten, während Go2, B2 und H1 unitree_go verwenden.

Debug Mode: vor jedem Low-Level-Test

Beim Einschalten startet der G1 seine eigene Motion Control, die weiterhin Befehle an die Motoren sendet. Wenn Sie parallel auf rt/lowcmd publizieren, kollidieren die Befehle und der Roboter vibriert. Das in der Deploy-Anleitung von unitree_rl_gym dokumentierte Vorgehen lautet:

  1. Schalten Sie den Roboter im Hebegeschirr hängend ein und warten Sie auf den Zero-Torque-Modus;
  2. Drücken Sie L2+R2 auf der Fernsteuerung: Der Roboter wechselt in den Debug Mode mit gedämpften Gelenken;
  3. Erst jetzt starten Sie das Low-Level-Programm.

Im Debug Mode hält der Roboter sein Gleichgewicht nicht selbst: Lassen Sie ihn hängen, bis Ihr Controller ihn trägt.

Erster Test: die Knöchel bewegen

Das Beispiel g1_ankle_swing_example (Quellcode in example/g1/low_level/) liest rt/lowstate, schreibt rt/lowcmd und lässt die Knöchel schwingen. Aus dem Ordner build:

./bin/g1_ankle_swing_example enp3s0

Ersetzen Sie enp3s0 durch Ihre Schnittstelle. Zeigt das Terminal "CRC Error", ist die empfangene Nachricht beschädigt oder entspricht nicht dem erwarteten Typ: Prüfen Sie Kabel, Schnittstelle und SDK-Version.

Für High-Level-Befehle (Stehen, Gehen mit vorgegebenen Geschwindigkeiten) gibt es g1_loco_client, das die integrierte Motion Control nutzt und daher außerhalb des Debug Mode gestartet wird:

./bin/g1_loco_client --network_interface=enp3s0 --get_fsm_id

Wichtigste Topics

rt/lowstateMotorstatus, IMU, AkkuBeispiel ankle swing
rt/lowcmdBefehle für Position, Geschwindigkeit, Drehmoment und kp/kd-GainsBeispiel ankle swing

Die Hände haben von der Lokomotion getrennte Topics: Es empfiehlt sich, den Regelkreis der Beine in einem Prozess und das Greifen in einem anderen zu halten, mit unterschiedlichen Frequenzen.

Zuerst simulieren: unitree_mujoco

unitree_mujoco ist ein auf MuJoCo basierender Simulator, der dieselben Nachrichten bereitstellt (LowCmd, LowState, SportModeState, IMU des Oberkörpers beim G1). Ein mit unitree_sdk2, unitree_sdk2_python oder unitree_ros2 geschriebenes Programm läuft zuerst in der Simulation und danach auf dem Roboter. Der Simulator unterstützt nur die Low-Level-Entwicklung. Für Reinforcement Learning deckt unitree_rl_gym den Zyklus Train, Play, Sim2Sim (MuJoCo) und Sim2Real für G1, H1, H1-2 und Go2 ab.

Wann ROS 2 dazukommt

Das direkte SDK ist der kürzeste Weg zu den Motoren und für isolierte Tests. ROS 2 brauchen Sie, wenn Sie Nav2, MoveIt, Standard-Vision-Pipelines, Aufzeichnung mit rosbag oder mehrere Roboter im selben Labor integrieren müssen. Das Paket unitree_ros2 enthält die unitree_hg-Nachrichten und ein Low-Level-Beispiel für den G1 (g1/lowlevel/g1_low_level_example); Unitree hat es auf Ubuntu 22.04 mit Humble (empfohlen) und auf Ubuntu 20.04 mit Foxy getestet. Installation, Netzwerk und erstes Topic finden Sie in der Anleitung ROS 2 auf Unitree-Robotern.

Sicherheits-Checkliste für das Labor

  • Erste Tests immer mit hängendem Roboter und freiem Umfeld.
  • Niedrige kp/kd-Gains und konservative Drehmomentgrenzen im ersten Regelkreis.
  • Eine Person an der Fernsteuerung, bereit, den Roboter in die Dämpfung zu bringen.
  • Dieselbe SDK-Version auf PC und Roboter; nach einem OTA-Update die Beispiele erneut prüfen.

Häufige Fragen

Lässt sich der G1 base (nicht EDU) programmieren?

Nein. Im offiziellen Unitree-Datenblatt ist die Sekundärentwicklung nur für den G1 EDU vorgesehen; der G1 base hat weder das Rechenmodul für die Entwicklung noch SDK-Zugriff.

Welches Betriebssystem braucht der Entwicklungs-PC?

Das README von unitree_sdk2 nennt Ubuntu 20.04 mit gcc 9.4.0 als Referenzumgebung, auf x86_64- oder aarch64-CPU. Für ROS 2 hat Unitree Ubuntu 20.04 mit Foxy und Ubuntu 22.04 mit Humble getestet und empfiehlt Humble.

Welche Adresse hat der Entwicklungscomputer des G1?

Der Entwicklungscomputer (PC2) des G1 EDU antwortet unter 192.168.123.164, Benutzer unitree. Ihr PC kommt in dasselbe Subnetz 192.168.123.x mit einer freien Adresse; Unitree schlägt 192.168.123.99 vor.

Warum vibriert der Roboter, wenn ich ein Low-Level-Beispiel starte?

Fast immer ist die integrierte Motion Control noch aktiv und sendet parallel zu Ihren Befehlen. Wechseln Sie in den Debug Mode (L2+R2 bei hängendem Roboter mit Dämpfung), bevor Sie Befehle auf rt/lowcmd senden.

Besser mit Simulation oder Hardware starten?

Mit der Simulation. unitree_mujoco verwendet dieselben DDS-Nachrichten wie der Roboter, daher läuft dasselbe Programm zuerst in MuJoCo und dann auf dem G1, wobei nur die Netzwerkschnittstelle geändert wird.
